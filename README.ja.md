Argus は、開いている Claude Code のセッションをすべて見張るローカルの Web ボードです。ターミナル・プロジェクト・
git worktree をまたいで、1 セッション 1 列で横に並べて表示します。名前は、すべての目を同時に閉じることのなかった
ギリシャ神話の百眼の巨人に由来します。

Claude Code の使い方は今までどおりです。Argus は Claude Code 自身のフックを通じて状況を受け取り、Mac 上の小さな
SQLite データベースに記録し、**http://127.0.0.1:7799** でページを提供します。どのセッションが何をしているか、
どれがあなたを待っているか、最後に何と答えたかが一目でわかり、正しいターミナルタブを探さずにそのまま返信できます。

> **Claude Code だけで動きます — 必要なのは Claude のサブスクリプションだけ。** Argus は Anthropic API を呼び出さず、
> API キーも求めません。ボード自体はモデルを一切呼び出しません。Claude を使う機能(ブレイン・日次ログ・カードチャット)は
> すべて、すでにログインしている `claude` CLI を通るので、Claude Code と同じプランの範囲で動きます。

## なぜ作ったか

複数の Claude Code セッションを並行して動かすと(リポジトリごと、worktree ごと、タスクごと)、すぐに追いきれなくなります。

- **どのセッションが何をしたか?** ターミナルのタブはどれも同じに見え、何を頼んだかをスクロールして探すのは手間です。
- **どこまで進んでいたか?** しばらく離れると、どれが終わってどれがまだ動いているのか、最後の答えが何だったのかがわかりません。
- **返事の見逃し。** 別のタブを見ている間に、あるセッションが終わったり権限確認で止まったりして、そのまま待ち続けます。
- **「次にやること」が頭の中にしかない。** まだ Claude に送る段階ではない、セッションごとの次の作業を置いておく場所がありません。

## できること

| | |
|---|---|
| 👀 **全部を一度に見る** | 1 セッション 1 列、最近のものから順に。プロジェクト・worktree・ブランチ・モデル・コンテキスト使用量つき。状態(*作業中*・*要確認*・*新しい応答*・*エラー*・*終了*)と、下のステータスバーに状態ごとの件数と Claude Code・Codex のセッション数(押すとそのエージェントだけ表示)。確認が必要になるとブラウザ通知と音でお知らせ。5 時間・週ごとの使用量バーと推奨ペース。 |
| 💬 **ターミナルを探さずに操作** | 返信(画像やドロップしたファイルパスも)、権限確認や質問への回答、作業の中断、名前の変更、このセッションだけのモデル・effort 変更、権限モード、巻き戻し、ブランチ・フォーク、スラッシュコマンド、セッションの終了。*tmux が必要です。* |
| 📝 **次にやることを管理** | セッションごとの「ネクストアクション」: Claude には送らないメモ、または今の返信が終わったら自動で送る予約。終了したセッションに残った TODO や、見落とした git 作業(未コミット・未プッシュ・PR のないブランチ)のレポート。 |
| 🔎 **話したことを何でも検索** | すべてのセッションのすべての質問と返答を全文検索(日本語・韓国語対応)。`argus-recall` スキルを使えば、どのセッションからでも Claude 自身が過去の会話を検索できます(「前回これどう直したっけ?」)。 |
| 🗂 **ターミナル・文書の列** | セッションの列の横にシェルの列とマークダウン文書の列。文書は列の中で直接編集でき、AI に「整理して」と頼むとそのファイルだけを直します。 |
| 🧾 **変更を確認** | セッションのフォルダごとの差分ビューア(未コミットの変更またはブランチ全体、統合・左右並び)。 |
| 📅 **振り返る** | 全セッションを時系列で並べたアクティビティと、毎朝書かれる日次の作業ログ(任意)。 |
| 🧠 **ブレインに頼む** *(任意)* | ボードを読める Claude Code セッションと会話:「何が私を待ってる?」「今日何をした?」「api セッションにテストを流すよう伝えて」。Slack や Gmail のメンションを受信箱のかんばんに集め、担当を提案し、カードをセッションに任せることもできます。 |

ボードの画面は 한국어・日本語・English に対応しています。ブラウザの言語に従い、⋮ → 🌐 で切り替えられます。

## クイックスタート

### 1. 必要なもの

- **macOS**
- **Claude Code** — Claude アカウントでログインした状態(サブスクリプションプランで十分、API キー不要)
- **Python 3** — Mac に入っている `/usr/bin/python3`(3.9 以上)。`pip install` するものはなく、直接呼ぶ必要もありません(`ctl.sh` が中で使います)
- **tmux** — `brew install tmux`。なければインストーラーが入れるか尋ねます
- **最近のブラウザ** — Chrome で確認済み

別途インストールするのは tmux だけです。セッション・ブレイン・ターミナルはボード専用の tmux サーバーで動き、ブラウザにそのまま表示されるので、ターミナルアプリは要りません。

> **この Mac で開発ツールを使うのが初めてなら:** Apple の *Command Line Tools*(git と Python 3)が必要です。
> 入っていなければ、下のインストールコマンドがインストーラーを開きます。**インストール** を押して数分待ち、コマンドをもう一度実行してください。

### 2. インストール

ターミナルに次の 1 行を貼り付けます。

```sh
curl -fsSL https://raw.githubusercontent.com/ygone-lee/argus/main/install.sh | sh
```

Argus を **`~/.argus`** フォルダにダウンロードしてインストーラーを実行します。インストーラーは Claude Code の設定
(`~/.claude/settings.json`)を先にバックアップしてから Argus のフックを追加します。ほかのフックや設定はそのままです。[OpenAI Codex](#openai-codex-のセッション) が入っていれば Codex のフックと `argus-recall` スキルも追加します。途中で次のことを尋ねます(該当するときだけ)。

| 質問 | 「はい」と答えると |
|---|---|
| tmux がないとき: Homebrew でインストールしますか? | `brew install tmux` を実行します。「いいえ」ならあとで自分で入れれば大丈夫です |
| 今ボードを開きますか? | ブラウザで http://127.0.0.1:7799 を開きます |

あとは今までどおり Claude Code を使うだけです。開いているセッションは次の質問から、新しいセッションは始まった時点でボードに現れます。
インストール前の会話もボードに取り込むには `~/.argus/ctl.sh backfill 7`(直近 7 日)を実行してください。

先に中身を見たい場合は [`install.sh`](install.sh)(約 40 行)を読むか、自分で clone してインストールできます。

```sh
git clone https://github.com/ygone-lee/argus.git
cd argus
./ctl.sh install
```

> この文書のコマンドにある `~/.argus` は、curl でインストールしたときの Argus フォルダです。clone した場合はそのフォルダのパスに置き換えてください。

### 3. Mac を起動したとき

ボードは Mac の中でバックグラウンドで動く小さなサーバー(http://127.0.0.1:7799)です。ターミナルを閉じても止まりません。
Mac を再起動すると、次のどちらかをするまでは止まっています。

- **Claude Code のセッションを 1 つ始める。** フックがボードをバックグラウンドで起動します。
- **`~/.argus/ctl.sh open` を実行する。** ボードを起動してブラウザで開きます(`start` は起動だけ)。

> **以前のバージョンにあった「ログイン時の自動起動」は当面なくしました。** macOS がログイン時に起動したサーバーは、
> プライバシー保護のためダウンロード・デスクトップ・書類フォルダを読めず、ボードにドラッグしたファイルを見つけられませんでした。
> ターミナルや Claude Code から起動すると、そのアプリと同じ権限を持ちます。以前オンにしていた場合は次のアップデートで
> ログイン項目が自動で削除されます。今すぐ削除するには `~/.argus/ctl.sh install` を実行してください。
> 自動起動は Argus を Mac アプリとして出したあとに戻す予定です。

### 4. よく使うコマンド

| やりたいこと | コマンド |
|---|---|
| ボードを開く(止まっていれば起動してからブラウザで開く) | `~/.argus/ctl.sh open` |
| ボードが動いているか確認 | `~/.argus/ctl.sh status` |
| ボードを止める · 再起動 | `~/.argus/ctl.sh stop` · `~/.argus/ctl.sh restart` |
| インストール状態の確認(何も変更しない) | `~/.argus/ctl.sh check` |
| インストール前の会話を取り込む(既定は直近 7 日) | `~/.argus/ctl.sh backfill 7` |
| デモボードを開く(架空のセッション、自分の設定には触れない) | `~/.argus/ctl.sh demo` |
| アップデート | ボードの ⋮ → ⟳ アップデートを確認、または上のインストールコマンド(curl の 1 行)をもう一度実行 |
| アンインストール | `~/.argus/ctl.sh uninstall` を実行してから `~/.argus` フォルダを削除 |
| コマンドの一覧 | `~/.argus/ctl.sh help` |

ボードが起動しないときは、`~/.claude/session-log/server.log` の末尾に理由が残ります。止める・再起動するコマンド(stop・restart)はボードのサーバーだけを
起動し直します。ボードターミナルで動いていたセッションは tmux サーバーにそのまま残ります。

### 5. アップデート

curl の 1 行でインストールした場合も、`~/.argus` は GitHub のリポジトリを取得したもの(git clone)なので、アップデートは GitHub から新しい変更を取り込みます(git pull)。

- **通知:** ボードのサーバーが数時間ごとに GitHub を確認します。新しいバージョンがあればボードの上に「🎉 Argus の新しいバージョン v0.2.0 が出ました · 変更点を見る · アップデート · あとで」の帯が出て、
  ブラウザ通知も 1 回送ります。「あとで」を押すと、そのバージョンは二度と出しません。
- **取り込み:** 「アップデート」(または ⋮ → ⟳ アップデートを確認)を押すと、変更を取り込み(fast-forward のみ)、インストーラーを再実行してフックを合わせ、ボードを再起動します。
  再起動するのはボードのサーバーだけで、セッションはそのままです。
- **設定(⋮ → ⚙ 設定 → アップデート):**

  | 項目 | 選べるもの |
  |---|---|
  | アップデートの方法 | **通知のみ**(既定) · **自動で取り込む** — 作業中や確認待ちのセッションがなく、ボードを 10 分以上使っていないときに取り込みます。取り込んだあと「✅ v0.2.0 にアップデートしました」の帯で知らせます · **オフ** |
  | アップデートのチャンネル | **安定版(リリースのみ)**(既定) — v0.2.0 のようなリリースが出たときだけ取り込みます · **最新版** — main のすべてのコミットを取り込みます |

未コミットの変更や未プッシュのコミットがあるフォルダでは取り込みません(開発中のフォルダを上書きしないように)。同じインストールコマンド(curl の 1 行)をもう一度実行してもアップデートされます。

### 6. はじめての使い方

1. ボードを開きます — http://127.0.0.1:7799
2. 上部の **＋ 新しいボード** → **✳ Claude Code** → フォルダを選ぶ → **作成**。ボードターミナルでセッションが始まり、列ができます。
3. 列の下の入力欄に依頼を書いて Enter。権限確認や質問にも列の中で直接答えられます。
4. 列の見出しの **⌨ ターミナル** でそのセッションのターミナルを、**💬 会話** で会話画面を表示します。
5. <kbd>?</kbd> を押すとショートカットの一覧が出ます — <kbd>⌘</kbd><kbd>1</kbd>〜<kbd>9</kbd> で列へ移動、<kbd>Z</kbd> で列を大きく表示、<kbd>/</kbd> で会話検索、<kbd>G</kbd> でクイック移動 …

すでにほかのターミナルで使っているセッションも、そのままボードに現れます。ボードから返信までするには、列の ⋮ → **⇄ ボードターミナルに移す** を押してください。

**まず見てみたいだけなら:** `~/.argus/ctl.sh demo` で、架空のプロジェクトとセッションが動く本物のボードが
http://127.0.0.1:7798 で開きます。専用の一時フォルダとポートを使い、あなたの Claude Code の設定には触れません。Ctrl+C で終了すると片付けます。

## 新しいボード: Claude Code · Codex · ターミナル · マークダウン

上部の **＋ 新しいボード** から 4 種類の列を作れます。どれも同じボードの列なので、先頭に固定、ドラッグで並べ替え、⌘数字での移動、
<kbd>Z</kbd> での拡大、保管が同じように使えます。

- **✳ Claude Code** — 選んだフォルダで Claude Code のセッションを開きます。モデル・effort・新しい worktree(`claude -w`)・最初のメッセージを選べます。
- **◎ Codex** — ボードターミナルで OpenAI Codex のセッションを開きます。モデル・推論レベル・最初のメッセージを選べます。Codex がインストールされているときだけ表示されます — [OpenAI Codex のセッション](#openai-codex-のセッション) を参照。
- **⌨ ターミナル** — 選んだフォルダでシェルを開きます。列そのものがターミナルです。
  - ボードの tmux サーバーで動くので、再読み込みやボードの再起動のあとも残ります。
  - `exit` すると「↻ 同じフォルダで開き直す」ボタンが出ます。
  - 列を削除するとシェルも閉じます。
- **📝 マークダウン** — 選んだフォルダの `.argus/boards/<名前>.md` に保存される文書です。そのリポジトリの `.git/info/exclude` に `.argus/` を追加するので、コミットには混ざりません。
  - **上(文書):** ✎ 編集と 👁 表示を切り替えます。変更はすぐ保存されます。表示ではチェックリスト(`- [ ]`)をクリックしてチェックできます。
  - **下(AI との会話):** 「議事録の形にまとめて」のように頼むと、Claude がそのファイルだけを編集します。ほかのファイル・コマンド・Web は使えません。
  - **元に戻す:** AI が編集するたびに、返答の下の「元に戻す」で編集前の内容に戻せます。
  - **モデル:** ⋮ → ⚙ 設定 →「マークダウンボードの AI モデル」(既定は Sonnet)。依頼のたびに Claude の使用量がかかります。
  - 列を削除しても文書ファイルはフォルダに残ります。

**任意の追加機能**

- **自分のターミナルアプリ** — なくても構いません。自分で起動したセッションもどこで動いていても記録され、ボードから返信・回答・操作まで
  するには任意のターミナルアプリ(iTerm2、Ghostty、ターミナル.app …)の tmux の中で動かします。すでに使っているなら Orca でも
  動きます。tmux の外の iTerm2・ターミナル.app のタブは前面に出せます。
- **Argus ブレイン** — Argus ロゴ横のブレインアイコンを押すか `B` キーで起動します。
- **コネクタ** — ⋮ → 🔌 コネクタで、Slack のメンション・DM と Gmail をブレインの受信箱に集めます。秘密情報は macOS のキーチェーンに保存されます。

**削除するには:** `~/.argus/ctl.sh uninstall`(clone した場合はそのフォルダで `./ctl.sh uninstall`)で
フックを外し、元のステータスラインに戻します。そのあと Argus のフォルダを削除してください。記録したデータは `~/.claude/session-log` に残ります。

## OpenAI Codex のセッション

[OpenAI Codex](https://github.com/openai/codex)(CLI・デスクトップアプリ)も使っているなら、その会話も Claude Code のセッションの隣に列として集まります。タイトルの前に Codex は OpenAI、Claude Code は Claude の印が付き、デスクトップアプリの会話には **Codex アプリ** のチップが付きます。オフにするには ⋮ → ⚙ 設定 → 「Codex のセッションも集める」。

- **見えるもの:** 会話、作業中・新しい応答・エラーの状態、実行中のコマンド・ツール呼び出し(作業の過程)、モデル・推論レベル、コンテキストの使用量。下のステータスバーの使用量に Codex の週間上限も出ます。検索・アクティビティ・ネクストアクション・日報にも含まれます。
- **新しく始める:** ＋ 新しいボード → **◎ Codex** で、選んだフォルダのボードターミナルに `codex` を起動します。モデル・推論レベル・最初のメッセージを選べます。
- **送る・止める・終える:** ボードターミナルで動く Codex には、列の入力欄の文をその入力欄に入れます。アプリの会話や、ボードが入力できないターミナルの CLI には `codex queue` でその会話に入れます。■ で止め(Esc)、⋮ → ⏻ で終えます(`/quit`)。終わった CLI の会話はボードターミナルで再開できます(`codex resume`)。
- **集め方:** `~/.codex` にある Codex の記録(`state_*.sqlite` のセッション一覧、`sessions/…/rollout-*.jsonl` と `thread_history_*.sqlite` の会話)を数秒ごとに読むだけで、書き換えません。インストール時に `~/.codex/hooks.json` にフックも追加し(既存のフックはそのまま)、「要確認」(承認画面)のような状態をすぐ受け取ります。Codex は新しいフックを一度だけ承認してもらいます — Codex CLI で `/hooks` を開いてください。フックがなくても、ほかは数秒遅れで同じように動きます。
- **Argus のあとで Codex を入れた場合:** ボードが気づきます。ボードの上に **フックを追加** の案内が出て、⋮ → ⚙ 設定 → **エージェント連携** でエージェントごとのフックの状態(Claude Code のフック *n/13*・ステータスラインのタップ、Codex のフック *n/9*・Codex の承認)を確認し、足りないものをボタンで追加できます。アップデートでフックが増えたときの Claude Code 側の再インストールもここから。Codex のフックの承認は Codex でしかできません — Codex CLI で `/hooks` を開いてください。ターミナルでは `~/.argus/ctl.sh install` が同じことを、`~/.argus/ctl.sh check` が全体の確認をします。
- **Codex のスキル:** インストーラーが Claude Code と一緒に `argus-recall` を `~/.codex/skills`(または `$CODEX_HOME/skills`)にも入れるので、Codex のセッションからも過去の Claude Code・Codex の会話を検索できます。Codex ではスキルを `/` ではなく `$` で呼びます — `$argus-recall` と入力するか、過去の会話についてそのまま聞いてください。⋮ → ⚙ 設定 → **スキル** でエージェントごとにインストール・削除できます。**削除** は Argus が入れたものだけを消し、削除したスキルはもう一度インストールするまでインストーラーやアップデートが入れ直しません(インストール時に外すなら `--codex-skills skip`)。リポジトリより古くなった写しはボード起動時に書き直します。
- **モデル・分岐・スラッシュコマンド:** ボードが入力できる Codex では、モデルのチップでこのセッションの `/model` を開き、⑂ で分岐(`/fork`、新しい worktree でも)やサイドチャット(`/side`)ができ、入力欄でスラッシュコマンドが補完されます。`/permissions`・`/review`・`/usage` などの選択画面はボードのポップアップで開きます。Codex アプリの会話は表示のみです。
- **Codex では使えないもの:** 権限モードのチップ(`/permissions` で)、巻き戻し、リモートコントロール、`/btw`(⑂ → `/side` で)。

## プライバシーと安全性

Argus は Claude Code の会話を保存するので、それを手元に置いたまま、邪魔をしないように作られています。

- **ローカルのみ。** サーバーは `127.0.0.1` でだけ待ち受け、`Host` ヘッダーを確認し、JSON のリクエストしか受け付けないので、
  ほかの Web ページから読み取ったり操作したりはできません。データはすべて `~/.claude/session-log`(SQLite とアップロード画像)にあります。
- **秘密情報は保存前に伏せます。** 既知のトークン形式(GitHub、Slack、Google、JWT)、`Bearer …`、URL 中のパスワード、
  `password=…` 形式の値は `[MASKED]` になります。それ以外は質問の中で `<private>…</private>` で囲めば、Claude には見え、Argus には `[private]` と保存されます。
- **隠れたモデル呼び出しも API キーもなし。** ボードの表示にトークンはかかりません。あなたが有効にしたり頼んだりした機能
  (日次ログ・ブレイン・カードチャット・マークダウン列の AI)だけが、あなた自身の Claude Code アカウントで Claude を動かします。
- **Claude Code 自体には手を加えません。** 会話記録を書き換えることはありません。`install.py` はほかのフックを残し、
  `settings.json` をバックアップし、`--uninstall` で元に戻します。フックが失敗しても Claude Code を止めません。
- **ターミナルへの入力は守られています。** セッションが確認待ちのとき、終了したとき、`claude` がそのターミナルの前面に
  いないときは入力しません。`!` で始まる文(シェルコマンドとして実行される)は、ボードの入力欄に直接打ってすぐ送ったときだけ受け付け、予約送信・ブレイン・受信箱からの依頼では受け付けません。複数の手順を踏む操作は毎回画面を確認し、
  合わなければ Esc で取り消します。
- **コネクタは読み取り専用です。** Slack は読み取り権限だけ、Gmail とカレンダーは件名・差出人・時刻だけを読みます(本文は読みません)。

## 制限と FAQ

- **今のところ macOS のみ。** ターミナル操作・キーチェーン・Spotlight は macOS の機能です。
- **セッションの操作には tmux が必要です。** ボードから起動したセッションはボード専用の tmux サーバーで動き、自分で起動したセッションは
  tmux(任意のターミナルアプリ)の中か Orca で動かすと操作できます。ほかのターミナルは前面に出せても入力はできません。対応ターミナルの追加は 1 ファイルです([Adding a terminal](docs/terminals.md))。
- **Claude Code の内部に合わせて動きます。** タイトル・要約・進行状況は会話記録ファイルから、ターミナル操作は画面から読み取ります。
  公開 API ではないためバージョンで変わることがあります。Claude Code 2.1.x で開発しています。更新後に動かなくなったら [issue](CONTRIBUTING.md) をお願いします。
- **Anthropic の API キーは必要?** 不要です。Claude が必要な処理はすべて `claude` CLI を通ります。
- **Claude の使用量を消費する?** ボードの表示では消費しません。日次ログ・ブレイン・カードチャット・マークダウン列の AI だけが、ほかの Claude Code の利用と同じくプランの使用量に数えられます。
- **VS Code や Claude デスクトップアプリのセッションは?** フックが動くセッションは記録されます。アプリを前面に出すことはできますが、入力はできません。

機能の詳しい説明、仕組み、拡張方法は [英語の README](README.md#feature-reference) を見てください。
